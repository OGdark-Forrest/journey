# Journey — Product Overview

Journey is a journaling phone app (Flutter, Android-first) that removes the blank-page
problem from journaling. Instead of writing an entry from scratch, the app generates a
mostly-prewritten journal entry and lets the user tweak only the parts that differ from
their normal routine.

## Core idea
1. A one-time **initial assessment** gets to know the user (routine, habits, preferences).
2. An algorithm (Python, running on a remote localhost service — built by another dev on a
   separate branch) produces a **prewritten journal entry** for the day.
3. The entry contains inline **"important areas"** (chips) — e.g. wake time, how you felt
   waking up, mood, meals. Each chip shows the user's *normal/default* value plus a button
   to **keep the default** or **edit** it if the day was different.
4. Each day's edits feed back into the algorithm to improve the next day's entry.

This is the **MVP**: fully **offline**, no accounts, no cloud, no auth.

## Post-MVP (not now)
- Cloud sync, which introduces a **paywall**. The paywall is what prompts the user to
  create an account / log in. No auth exists before that point.
- A **suggestions / reflections / insights** section powered by LLMs — e.g. a happiness or
  wellness score, generated on demand after MVP.

## Log entry model
- There are **multiple log entries per day**. Fields vary by which entry it is (e.g. don't
  ask for wake time on the 2nd entry of the day).
- User can log using two different modes:
  - **Normal** — a ~30-min-interval time field defaulting to current time, a happiness
    scale (mascot reacts to the value), and the specific event info needed.
  - **Blitz** — a fast, low-friction log; generated instantly from previous logs or hardcoded data/prompts.
- Number of chips `n` per entry defaults to **10** and is **user-customizable**. Higher `n`
  = more accuracy/understanding but more time per entry.
- Each chip has ~4 preset options + a 5th **custom** option.

## Screens (MVP)
- Splash
- Initial assessment (in-depth onboarding, shown once on first launch)
- Main dashboard (home; scrollable log history / new entry)
- Log history
- Log entry page (the core screen — prewritten entry with editable chips)
- Settings (small user preferences only — no account section in MVP)
- Suggestions / reflections / insights (post-MVP; generated on request)

## Gamification (tone: "engaging, but it's still a journal")
- **Streaks** (no XP).
- Mascot: an **otter**. Reacts to happiness scale on normal logs.
- Confetti / celebration animations on meaningful completions.
- Rounded-rectangle cards, satisfying button feedback.
- The gamification exists to make the app inviting to return to; the real hook is not
  having to write from scratch. Do not over-gamify.
