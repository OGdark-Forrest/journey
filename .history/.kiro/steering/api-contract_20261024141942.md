# Journey — Flutter <-> Python API Contract (DRAFT)

Shared reference between the frontend (Flutter) and backend (Python, separate branch).
Status: **draft / proposed** — agree changes with both sides before implementing.

## Transport
- The Python program is embedded in the app with **serious_python** and runs a small HTTP
  server on the device's **localhost** (`127.0.0.1`). Flutter calls it with the `http` package.
  Flutter never calls Python functions directly.
- Port: passed from Flutter to Python via `SeriousPython.run(environmentVariables: {...})`
  as `JOURNEY_PORT` (avoid hardcoding a port that could collide).
- Auth token: Flutter generates a random token per launch and passes it as `JOURNEY_TOKEN`.
  Every request must send `Authorization: Bearer <token>`; Python rejects anything else.
  Reason: any app on the device can reach `127.0.0.1`, and journal data is sensitive.
- JSON request/response bodies, UTF-8. Times are local `HH:mm`; dates are `YYYY-MM-DD`;
  timestamps are ISO 8601.

## Lifecycle
- On app start: `SeriousPython.run()`, then poll `GET /health` until it responds or a
  timeout is hit (first Android launch is slower — Python app is unpacked once).
- On app resume: re-check `GET /health`; restart Python if it's gone (Android may kill the
  process in the background).
- Storage (open question): proposed that **Python owns the SQLite DB**, written under its
  working directory (serious_python sets this to a writable per-app data dir). Flutter stays
  a thin client.

## Endpoints

### `GET /health`
`200 { "status": "ok", "version": "0.1.0" }`

### `GET /assessment/questions`
Returns the initial onboarding questions.
```json
{
  "questions": [
    { "id": "usual_wake_time", "prompt": "When do you usually wake up?", "type": "time",
      "options": ["06:00", "07:00", "08:00", "09:00"], "allowCustom": true }
  ]
}
```
`type`: `time` | `single` | `multi` | `scale` | `text`

### `POST /assessment`
```json
{ "answers": [ { "questionId": "usual_wake_time", "value": "07:30" } ] }
```
`201 { "completed": true }`

### `GET /assessment/status`
`200 { "completed": true }` — drives the first-launch redirect to onboarding.

### Entry model
**One entry = one event.** Every entry has exactly **3 fields**:
1. **Time** — when the event happened. 30-min intervals, defaults to now (rounded).
2. **Happiness** — a scale; drives the otter mascot's reaction.
3. **Event chip** — what happened. ~4 preset options + a 5th custom option.

The user logs up to **`n` entries per day** (`entriesPerDay` pref, default **10**,
user-customizable). Each entry covers a single event/area/subject, so 10 is a reasonable
daily default. Higher `n` = more understanding for the algorithm, more time spent per day.

Happiness scale is **1–5** (5 otter expressions).

### Daily wake-up time
Separate from the `n` entries. One per day, picked in **30-min steps**; defaults to the
user's standard wake time (learned from the assessment, then from history).

`GET /day/YYYY-MM-DD`
```json
{
  "date": "2026-10-24",
  "wakeTime": { "value": null, "default": "07:30", "intervalMinutes": 30 }
}
```
`value` is `null` until the user confirms or changes it.

`PUT /day/YYYY-MM-DD/wake-time`
```json
{ "value": "08:00", "keptDefault": false }
```
`200 { "date": "2026-10-24", "wakeTime": { "value": "08:00", "default": "07:30" } }`

### `GET /entries/draft?mode=normal|blitz`
Returns the next prewritten entry. The **server predicts all 3 defaults** from the user's
history and time of day (e.g. the first entry of the morning is likely "Woke up").
```json
{
  "draftId": "d_123",
  "mode": "normal",
  "indexToday": 3,
  "entriesPerDay": 10,
  "template": "At {time} I {event} and felt {happiness}.",
  "time": { "default": "14:30", "intervalMinutes": 30 },
  "happiness": { "min": 1, "max": 5, "default": 3 },
  "event": {
    "default": "had lunch",
    "options": ["had lunch", "went for a walk", "worked", "met a friend"],
    "allowCustom": true
  }
}
```
- `template` tokens `{time}`, `{event}`, `{happiness}` are rendered inline as tappable chips.
- `indexToday` is 1-based (this is the 3rd entry today).
- **Blitz** uses the same shape; the server returns defaults it's most confident in so the
  user can save in one tap. Can be generated from previous logs or hardcoded prompts.

### `POST /entries`
```json
{
  "draftId": "d_123",
  "mode": "normal",
  "time":      { "value": "14:30",         "keptDefault": true },
  "happiness": { "value": 4,               "keptDefault": false },
  "event":     { "value": "ate with team", "keptDefault": false, "custom": true }
}
```
`201 { "entryId": "e_456", "indexToday": 3, "streak": { "current": 5, "best": 12 } }`
`keptDefault` per field is the signal the algorithm uses to learn the user's normal day.

### `GET /entries?from=YYYY-MM-DD&to=YYYY-MM-DD`
Log history for the dashboard list (newest first).
```json
{
  "entries": [
    { "entryId": "e_456", "date": "2026-10-24", "time": "14:30", "mode": "normal",
      "happiness": 4, "event": "ate with team",
      "text": "At 14:30 I ate with team and felt 4/5." }
  ]
}
```

### `GET /streak`
```json
{ "current": 5, "best": 12, "loggedToday": 3, "entriesPerDay": 10, "streakMinEntries": 1 }
```
Streak rule: a day counts toward the streak once `loggedToday >= streakMinEntries`.
`streakMinEntries` is a **config value, default 1** (not a user setting for now). The
server owns the rule; the frontend just renders `current` and `loggedToday / entriesPerDay`.

### `GET /prefs` / `PUT /prefs`
```json
{ "entriesPerDay": 10, "reminderTime": "21:00", "theme": "system", "displayName": "Alan" }
```
`entriesPerDay` default 10 (TBD), user-customizable.
